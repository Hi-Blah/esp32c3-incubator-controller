# NAS记录器2.2.3a：历史时间修复性能补丁

[English](nas-2.2.3a.md)

本补丁用于已部署的NAS-Recorder-2.2.3。开发板继续使用Connected-2.2.3；保留现有MQTT权限、Compose配置、凭据和数据库。

## 问题及修复后的行为

旧版每接收一条带时间锚点的缓存采样，都会对本次开机的整段温湿度、光照历史执行关联更新，相关查找又缺少合适的索引。历史增长后，单条消息可能长时间占住数据库写入及MQTT接收回调，超过记录器60秒心跳周期，表现为约90秒后被broker判定超时、循环重连，以及后台持续报告数据库忙。记录器客户端与开发板客户端是两条不同连接，应先核对日志中的客户端名称。

新版通过部分索引只选择尚未定位时间、或等待NTP提高时间质量的NAS记录；每批最多处理128条缓存记录，并按主键定位对应历史行。其余由后台分批继续处理。后台取得短写事务后重新读取时间锚点，防止旧NAS估计覆盖新NTP锚点。不再反复改写已有可信NTP历史，同时保留提交后回执、仅修复同次开机时间和历史不触发实时警报的规则。

记录器增加慢消息耗时、数据库实际错误码和MQTT断开原因日志。`/assets/ready`显示`NAS-Recorder-2.2.3a`。

## 从现有2.2.3升级

1. 保留SQLite一致性备份，以及当前`sample_journal.py`、`recorder.py`、`dashboard.py`的备份。
2. 将三个文件替换到记录器实际挂载的源码目录。沿用此前并排升级时，即原recorder目录下的`upgrade-2.2.3/recorder/`。不要只替换已经停用的旧目录副本。
3. 在原Compose目录执行下面一条命令，只重建记录器，让文件挂载读取新版：

~~~sh
sudo docker compose -f compose.local.2.2.3.yaml up -d --no-build --pull never --force-recreate recorder
~~~

4. 检查启动日志和`/assets/ready`，至少对照观察10分钟broker日志及实时数据年龄。重启时会有正常重连；反复90秒记录器超时和数据库忙应停止。若开发板仍断线，再单独检查其无线及传输路径。

无需删除历史行、WAL/SHM文件或配置密码。两个小索引自动建立，不需要手动重建数据库或执行`VACUUM`。较多未定位时间的记录将逐批补齐。

## 验证及限制

2026-10-18，本地使用随包paho-mqtt 2.1.0完成148项NAS测试。新增回归覆盖查询工作量有界、可信历史不重复改写、后台分批修复、失败回滚不发回执及并发NTP锚点更新。其中两项可在原2.2.3上复现失败。

按2,133条缓存、48,649条温湿度、205,602条光照记录构造同次开机模拟库，旧版处理一条可信新采样在100秒后仍未完成；修改后同一项测试约16毫秒。这是开发电脑的模拟测量，不是现役数据库或NAS实测。恢复效果和长时间稳定性仍需部署后观察。
