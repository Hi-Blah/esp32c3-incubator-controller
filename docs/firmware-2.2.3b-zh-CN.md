# Connected-2.2.3b：本机网页资源处理修复

[English](firmware-2.2.3b.md)

本次固件修复2.2.3中两处本机HTTP缺陷，仍需实机验收。兼容NAS-Recorder-2.2.3a，无需为本次固件修改再次更新记录器、Compose、ACL或数据库。

入口页此前轮询完整的`/api/state`，包含两路程序和诊断信息；现在改用经过登录验证的`/api/entry`，只读取跳转、时钟、Wi-Fi及配网所需信息，响应不足512字节。两个接口复用已有HTTP快照，不再新增一份程序快照。

入口页此前只允许向本机发起请求，导致浏览器拦截其对NAS的就绪检查。现在只为入口页额外放行编译时指定的NAS地址。本机完整页和API仍保留同源策略、登录和CSRF检查。编译前在`web_entry.h`设置`INC_NAS_WEB_ORIGIN`。

页面及状态接口在发送成功响应头之前检查内存。不足时返回HTTP 503、`Retry-After: 10`和简短说明；直接打开页面时还提供NAS入口。如果发送过程中内存持续不足，约100毫秒后终止等待，不再为内存恢复占住整个15秒页面传输期限。每次最多发送512字节和原有内存余量不变；网络传输仍有独立的总超时限制。

这不会增加RAM，也不保证完整备用页面能与所有网络任务同时运行。日常使用NAS的`/device/`，`/local`作为备用。出现503表示网页资源不足，不代表光源指令执行失败。

排查对照中，关闭开发板直连网页后NAS更新恢复，数据年龄0.7秒、剩余内存约25KB，历史最低仅648字节。这支持网页资源压力参与故障的判断，但不能据此认定每一次MQTT断开都由同一原因造成。记录器数据库超时另见[NAS 2.2.3a说明](nas-2.2.3a-zh-CN.md)。

验收时先只观察NAS/HA，再单独打开开发板入口，确认转到正确的NAS地址。另行检查`/local`：应完整加载或明确显示繁忙，避免长时间停在未完成的加载中。对比前后boot ID、缓存内存、数据年龄和broker断开日志。开发工具未执行刷板或实机验证。
